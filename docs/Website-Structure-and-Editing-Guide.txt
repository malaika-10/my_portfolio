1. HOW THE WEBSITE WORKS
=======================
This is a static website built with HTML, CSS and JavaScript.
There is no database, admin panel, CMS, framework or automatic project catalogue.

HTML = content, links, image/video references and page structure.
CSS = appearance, spacing, colours, typography and responsive layouts.
JavaScript = eye tracking, video compositing, navigation and animations.
Assets = image, font and video files loaded by the pages.

A folder containing index.html becomes a URL directory on GitHub Pages.
For example, pages/shama/index.html becomes /pages/shama/ under the site base URL.
The expected site base is https://malaika-10.github.io/my_portfolio/ if GitHub
Pages is enabled for this repository. Publishing settings must be checked in
GitHub; changing the repository remote does not enable Pages automatically.

============================================
All homepage markup and written content are in the root index.html.

  the Curiosity.
  Four cards: Interaction Design, Motion & Animation, Visual Design, and
  Research & Strategy.
  Main layout: assets/css/home.css.
  Current overrides, full-width justified paragraph and card grid:
  assets/css/home-updates.css.

Section 04 — Featured projects:
  <section class="section projects" id="projects">
  Three manually written project cards in index.html.
  Each card contains a detail-page href, thumbnail src, category, title and
  Explore label. The View All Projects button links to pages/all-projects/.

  <section class="section connect" id="connect">
  Heading, description, email, location, Behance and LinkedIn are in index.html.

  Current video: assets/videos/contact-artist-latest.mp4.

Changing text or links in a page affects only that page. The gallery has its own
header/footer markup, and detail pages have their own navigation/footer markup.
They are not generated from a single shared HTML component.

4. SHARED STYLES AND JAVASCRIPT
===============================
assets/css/base.css
  Site colour variables, spacing tokens, typography defaults, reset, containers,
  buttons and shared utilities. Changes can affect many pages that load it.

assets/css/components.css
  Navbar, mobile navigation and footer styles for pages loading this stylesheet.

assets/css/home.css
  Original homepage layouts: hero, about, projects and contact.

assets/css/creative-profile.css
  Section 02 columns, character positioning, education/tools text and decoration.

assets/css/home-updates.css
  Current homepage refinements: branding, spacing, section 03 paragraph/statistics,
  skill-card layout, contact frame and project poster-card presentation.
  Also loaded by All Projects, which shares the poster-card design.
  Loaded late, so its rules can override home.css and components.css.

assets/js/main.js
  Sticky navbar state, mobile menu opening/closing and scroll-reveal animations.

assets/js/creative-profile.js
  Moves the homepage character's pupils toward the pointer. Handles motion
  preferences and recentres the pupils when the pointer leaves/window blurs.

assets/js/contact-artist.js
  Displays the contact animation with transparency using WebGL and a Canvas 2D
  fallback. Controls visible-area playback and reduced-motion behaviour.
  IMPORTANT: the current MP4 contains colour on the left and its opacity mask
  on the right. It is not an ordinary full-width MP4. Do not simply replace it
  with a regular MP4 without preparing the same packed format or updating the
  renderer. The visible canvas is 720 x 1280; the packed video is 1440 x 1280.

CSS/JS references sometimes include ?v=6 or another version string. When changing
an existing stylesheet or script, update its version in the HTML if necessary
so visitors load the revised file rather than a cached copy.

6. TEXT INSIDE SLIDES VERSUS REAL HTML TEXT
==========================================
Most project slides are rendered images, not editable HTML layouts.

To change visible words embedded in a slide:
  1. Update the original PDF/PowerPoint/design or rebuild that slide.
  2. Export the revised slide artwork.
  3. Replace its image assets or update their paths in the detail-page HTML.
  4. Update the matching screen-reader transcript/alt text.

A <p class="sr-only"> beside a slide is an accessibility transcript. Changing it
alone does NOT change the words visible inside the slide image.

Exceptions: Shama's project overview/deliverables and the homepage copy are real
HTML text. Edit their HTML directly.

Animations/videos are overlays above clean slide backgrounds. When replacing a
static character/image with animation, remove the original object from the slide
background first; otherwise the old image can show through behind the animation.
Overlay positions use percentages and must match each specific slide's layout.

8. HOW TO ADD A NEW PUBLIC PROJECT
=================================
Example name: New Project. URL slug: new-project.

Step 1 — Create the detail page:
  Create pages/new-project/index.html and pages/new-project/index.css.
  Use an existing linked project page as a template, replacing its project-specific
  title, metadata, slide markup, accessibility text and asset references.
  Only add project.js if the new page actually needs video or other interaction.
  Do not copy Pindi media overlays into an unrelated project unchanged.

Step 2 — Add assets:
  Put its slide images in assets/images/new-project/hd-layout/.
  Put its poster in assets/images/project-thumbnails/.
  Put any normal playable project videos in assets/videos/.

Step 3 — Add a card to the All Projects gallery:
  Edit pages/all-projects/index.html.
  Copy a project-card inside .projects__grid and update href, image, alt text,
  project number, category and title.

  Example (inside pages/all-projects/index.html):

  <a href="../new-project/" class="project-card">
    <span class="project-card__number">04</span>
    <img class="project-card__image"
         src="../../assets/images/project-thumbnails/new-project.png"
         alt="New Project cover" loading="lazy">
    <div class="project-card__overlay">
      <span class="project-card__tag">UI/UX / Interaction</span>
      <h3 class="project-card__title">New Project</h3>
      <span class="project-card__link">Explore →</span>
    </div>
  </a>

Step 4 — Homepage featuring is optional:
  Edit root index.html only if the project should be one of the THREE featured
  homepage projects. Replace an existing featured card rather than adding a fourth.
  Root-page paths differ from gallery paths:
    href="pages/new-project/"
    src="assets/images/project-thumbnails/new-project.png"

Step 5 — Navigation and metadata:
  Set the detail-page <title>, description and favicon.
  Add suitable Back to home / Back to all projects links.
  Keep slide images non-clickable; do not add zoom buttons/viewer dialogs.

Step 6 — Check and publish:
  Verify every image/video loads, all links work, and the layout fits desktop
  and mobile. Ensure there is no horizontal scrolling.
  Commit and push to index-page-layout. Wait for a successful GitHub Pages build.

9. HOW TO ADD A NEW UNLISTED PRESENTATION
=======================================
Use the standalone convention, for example project04/:
  project04/index.html
  project04/index.css
  project04/project.js              Only if needed
  assets/images/project04/hd-layout/

Use ../assets/... paths because this folder is one level below the site root.
Include <meta name="robots" content="noindex, nofollow"> if it should be unlisted.
Do not add its link to index.html or pages/all-projects/index.html.
It will still be publicly accessible at <site-base>/project04/.

GitHub Pages paths are case-sensitive. A filename must match exactly, including
spaces, uppercase/lowercase letters and its extension. Prefer simple lowercase
names with hyphens for newly added website files.

12. LOCAL PREVIEW AND DEPLOYMENT
================================
From the repository root, run:
  python3 -m http.server 8000
Then open the local server in your browser for development.
No npm install or compilation step is required for this website.

GitHub Pages setup:
  Repository: malaika-10/my_portfolio
  Branch used for work: index-page-layout
  Pages deployment source: index-page-layout, root folder (when using branch deploy)
  .nojekyll: keep this file at the repository root.

Check deployment status in the repository's Settings > Pages and Actions.
A successful git push does not itself confirm that the Pages deployment finished.

Never put passwords, private keys or tokens in HTML/JS/assets or this repository.
Publicly served images and videos can be copied or screenshotted even when
click-to-enlarge is disabled.
